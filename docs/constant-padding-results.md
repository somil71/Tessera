# Constant-built spatial padding

Recorded 2026-11-25. The local graph analyzer now accepts `Pad` in constant mode when its eight int64 widths come from an initializer or a constant-only ONNX branch. It evaluates only that branch, limits each `ConstantOfShape` allocation to 64 elements, requires nonnegative spatial-only padding, and requires an optional fill value to be a finite FP32 scalar. Shape-only `Reshape` and `Transpose` can participate in the widths branch. Dynamic widths derived from image data or image dimensions are rejected.

The [live fixture](../tests/fixtures/smoke_constant_of_shape.py) builds widths through `ConstantOfShape → Reshape → Transpose → Reshape → Concat`, then uses them in `Pad → Conv → Relu`. The derived halo is one pixel on both axes. A 37×53 three-band georeferenced raster completed in twelve tiles through both fixed and automatic schedules under a 128 MiB hard Job Object cap. Both FP32 outputs matched an unsplit ONNX Runtime reference at every pixel; CRS and transform matched. Recorded raw job peaks were 84,189,184 bytes fixed and 87,805,952 bytes automatic. A modified graph with channel padding was rejected before inference. Rust unit tests cover inferred `Constant` shape/type and static Pad shape; the generic local and shape-built Resize raster fixtures still pass.

This extension advances the exposed FTP-B3 graph past its constant padding branches, but that model remains unsupported: its first unmet operation is `GlobalAveragePool` at node 40. The earlier [frozen holdout failure](ftp-b3-holdout-result.md) remains the independent evaluation result. Supporting FTP-B3 later would be development work and would still require a newly frozen unseen model for the feasibility decision.
