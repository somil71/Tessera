# SCUNet replacement holdout result: failed preflight

Recorded 2026-11-24. The planner implementation, reserved model and inputs, 1 GiB/two-thread configuration, and [manual candidate list](scunet-holdout-freeze.md) were frozen in Git commit `8bfea7e8c4d83605f462821ff81d51e79ace231a` before model download or graph access. The candidate-file SHA-256 is `22e5d64fcd1cafa9294dde73fd6100bfaae3b97f86f62e0d3cbdb0f37c01bc9b`. The baseline tuner was not run because there is no supported automatic schedule; the frozen list remains unchanged.

The pinned [Heliosoph SCUNet export](https://huggingface.co/Heliosoph/scunet-onnx) at revision `6d11417ee2fbcc73783c502a238ac115097754fe` downloaded with the frozen hashes: graph `76170f1fcb84d3b3d38c4e7133a658bbbb70504e3dc5e4e4d1f7b0c395c093be` (3,795,638 bytes) and external data `f46aa0f533e5bb8b2485a6531a205e270f4a7be2447880a12d97f5f00b1e70c9` (73,138,176 bytes). The 2,122-node graph has one three-band FP32 input and output. Its operators include `Squeeze`, `LayerNormalization`, `Einsum`, `Softmax`, and `MatMul`.

`tests/performance/create_scunet_holdout.py` generated the exact reserved NumPy 2.4.6 RGB rasters. Their GeoTIFF SHA-256 hashes are `c4147e9461de99b1ee7813ffcd92b1e3c6cd34d989732141276164107a4612a2` (seed 5201, 64²), `52c4a921dcc84bd826bdc927edea4d49c31d2f26cc501e539a27a0f2f65e9fbc` (seed 5202, 128²), and `f574d0f4af034d4004f56c96f9d80c7f1c5d9229446f32d4cccf25e2f3d10fdd` (seed 5203, 512²). They use EPSG:32643, unit-pixel transform from `(500000, 2000000)`, and no nodata.

An installation doctor report for the 64² pair and automatic runs for both 64² and 128² rejected the graph **before inference**: first unsupported node 2, `Squeeze`, has no validated raster schedule. The automatic 64² failure artifact is `runs/holdout/scunet/auto-64.plan.failure.json`; its job peak was 121,184,256 bytes under the requested 1,073,741,824-byte cap. The 128² failure is analogous. No output raster was published. Unsplit ONNX Runtime references completed for both small inputs, with output hashes `73a4c936fd6761f095840ca5c970dda443bc0b46d5a01d810b65100cd8a08bfb` and `bcb92ba09fd2267e1dd7f9ff5a0b66c63766f043daf81131b73b8dc17c5b9538`.

Under [evaluation amendment 3](evaluation-amendment-3.md), an unsupported graph is a **failed held-out case**. The 512² performance case has no feasible pre-run schedule under the frozen implementation, so no timed run, four-hour tuning attempt, or five-pair benchmark can establish a performance pass. This model is now exposed development material. Supporting it later would require a newly frozen independent replacement holdout. The result is a real generality limit, not evidence that the other supported model families are incorrect.
