# Amendment 5: independent FTP-B3 holdout

Frozen 2026-11-24 **before downloading or inspecting the ONNX graph**. Earlier SCUNet and FraXet holdouts failed compatibility preflight and were exposed; neither may be used as unseen evidence. This amendment designates a new externally authored model and fixed evaluation settings. Model and input byte hashes will be recorded from the pinned artifacts before preflight; recording hashes is not permission to alter the protocol after graph inspection.

## Selection from published metadata

The [Fields of the Planet model card](https://huggingface.co/fieldsoftheworld/ftp-b3) describes `ftp-b3.onnx` as a dynamic-height/width FP32, single-input, three-class raster segmentation U-Net with eight input bands. The model is trained on paired PlanetScope seasons at 3 m resolution, and the weights have a CC-BY-NC-4.0 license. We selected it from that published input/output description, without viewing its operator graph or executing it.

- Exact repository revision: `301701bb04e62b1b55c7d807556a53600e6f386a`.
- Model URL: `https://huggingface.co/fieldsoftheworld/ftp-b3/resolve/301701bb04e62b1b55c7d807556a53600e6f386a/ftp-b3.onnx`.
- Local model: `models/holdout/ftp-b3.onnx` (downloaded artifact, ignored by Git).
- Local input: `data/holdout/ftp-b3/ftp-b3-512.tif`, generated by `tests/fixtures/create_ftp_b3_holdout_input.py` with seed 5107. It is synthetic FP32 eight-band data with EPSG:32643 and 3 m affine pixels. Synthetic values exercise execution correctness only; they do not establish map accuracy on PlanetScope imagery.

## Frozen decision settings

1. Preflight checks the model's declared tensor contract and supported graph schedule without running raster inference. A rejection is recorded as a failed holdout; subsequent operator support work treats the model as exposed development material.
2. If supported, use a 512×512 whole-image ONNX Runtime FP32 output on the exact input as the numerical oracle. Require maximum absolute error ≤ `1e-4` and maximum eligible relative error ≤ `1e-3` where the reference magnitude is at least `1e-3`. Compare all scores and georeferencing.
3. Automatic and manually tuned runs use the same Windows CPU, a hard 1 GiB Job Object committed-memory limit and at most two inference threads. Record both outer and selected-execution raw job peaks. Any unexplained peak above cap prevents a clear pass under [amendment 2](evaluation-amendment-2.md).
4. Before automatic inference, freeze the manual candidate list and four-hour tuning allowance. Retain every candidate attempt and the selected fastest cap-valid, reference-matching baseline. An independent tuner is preferred; if the developer tunes it, identify that limitation.
5. Alternate order for one first pair and five repeated pairs. Require the same correctness and memory criteria in every run and repeated median end-to-end automatic runtime ≤ 1.25× the tuned baseline. A ratio > 1.5× is a performance failure; the gap between is inconclusive.

This is one held-out model-machine pair. Even a pass does not establish the broader v1 completion criteria, a cross-machine claim, or independent user adoption. No PlanetScope imagery is redistributed in this protocol.
