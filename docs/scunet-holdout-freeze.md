# SCUNet independent evaluation freeze

Recorded before downloading, opening, preflighting, or running the [reserved model](evaluation-amendment-3.md). The candidate list is [`evaluation/scunet-manual-candidates.json`](../evaluation/scunet-manual-candidates.json). It includes tile sizes 64, 128, 256, and 512, both RAM and disk boundary storage at cut 0, and two single-thread alternatives. These choices use only the model card's divisible-by-eight spatial contract. No graph-specific cut is assumed. The baseline tuner may execute this list for at most the frozen 240-minute allowance and must retain failed attempts. If this list cannot yield a valid baseline, the evaluation is inconclusive or failed under the existing protocol; it will not be edited after model exposure.

Reserved machine and configuration: Intel Core i5-13450HX (10 physical cores, 16 logical processors), 34,053,414,912 bytes installed RAM, Windows, Python 3.11.6, NumPy 2.4.6, ONNX 1.23.2, ONNX Runtime CPU 1.31.0, rasterio 1.4.4. The job-wide committed-memory limit is 1,073,741,824 bytes; each scored automatic run uses two execution threads. The CPU affinity mask is all 16 logical processors (`0xFFFF`) for automatic and baseline runs. Work, spill, outputs, and temporary files use drive `E:`. The recorded model and candidate file hashes and the Git commit that includes this freeze must be captured before exposure; later trial manifests must include the generated input hashes.

The 512×512 performance case receives a bounded pre-run time estimate before execution. A model with unsupported operators or nonlocal dependencies is rejected rather than tuned into support after exposure. The whole-image 64² and 128² correctness cases and the 512² performance case remain exactly as frozen in amendment 3.
